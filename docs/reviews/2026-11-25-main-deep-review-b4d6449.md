**Verdict — Blocked.** The release can overwrite an existing OpenCode plugin, accept privileged state changes from unauthenticated local clients, hand private replies to an unverified local service, and fail to launch on Intel Macs. The playback queue and history persistence also have release-blocking failure paths.

## Sentry Security Review

Security confidence is High for S01–S03. S04–S06 are conditional or operational findings recorded with their constraints. The app runs as the logged-in user, the CLI and Claude mod cross a TCP boundary, and the bundled app starts a second HTTP service for MLX. The review distinguishes those channels from same-user files and intentional external package/model downloads.

### S01 · High · Local clients can control Readback without authorization

**Evidence and trigger.** The listener binds to IPv4 loopback. Every request reaches the same router, which makes its decision on HTTP method, path, and body. It checks neither caller identity nor an application credential. A local process with loopback access can change saved settings, start or stop speech, initiate engine install or removal, and request playback of session history. Health includes the current session identifier during playback. The optional MLX process exposes a second unauthenticated surface while it runs, including model management, and the pinned server defaults to wildcard CORS. No browser reachability was established. [ControlServer.swift](../../Sources/Readback/ControlServer.swift#L53), [AppDelegate.swift handlers](../../Sources/Readback/AppDelegate.swift#L288), [AppDelegate.swift status](../../Sources/Readback/AppDelegate.swift#L373), [SpeechMakers.swift](../../Sources/Readback/SpeechMakers.swift#L392), [MLX Audio 0.6.7 server](https://github.com/Blaizzy/mlx-audio/blob/v0.6.7/mlx_audio/server.py)

**Fix.** Authenticate callers before handling the request. Prefer owner-restricted local IPC for app clients, or require an installation-scoped credential with strict request validation if TCP is required. Keep the MLX service private to its owning app, narrow its exposed operations, and disable broad CORS.

### S02 · Critical · Clients can send private reply text to an unverified listener

**Evidence and trigger.** If another local service owns the control port and answers health with HTTP 200, the Swift CLI considers Readback up and posts the full reply. The Claude mod trusts a successful decoded response on the same port before posting the last reply. On the MLX port, the app logs an unrelated listener and leaves it in place. It then accepts HTTP 200 as readiness and sends synthesize requests carrying reply text. The default app cannot establish that either listener belongs to its expected peer. No interception was attempted. [CLI request and readiness](../../Sources/readback-cli/main.swift#L62), [CLI reply payload](../../Sources/readback-cli/main.swift#L219), [Claude mod](../../integrations/claude-code/readback/hooks/register.tsx#L21), [MLX readiness](../../Sources/Readback/SpeechMakers.swift#L174), [MLX request](../../Sources/Readback/SpeechMakers.swift#L209), [Stray handling](../../Sources/Readback/SpeechMakers.swift#L261)

**Fix.** Verify the peer before sending any transcript, fail closed on port collisions, and disallow redirects for app-owned IPC. For MLX, tie readiness to the launched child and private transport.

### S03 · High · Hook diagnostics can retain original prompt text and session metadata

**Evidence and trigger.** A rejected command-like Codex prompt matching the diagnostic heuristic is lowercased and logged with up to its first 60 characters. An ordinary prompt can match and leave user text in `cli.log`, including any sensitive content in that prefix. The app also stores session identifiers, project-derived titles, and part of an unrelated process command line on a voice-port collision. It marks all unified-log messages public. Clearing reply history leaves these log copies in place. The installed history and CLI log each had file mode `0644`. The installed user's Library directory was `0700`, so the mode observation alone does not establish cross-account reads on this machine. [CLI logger](../../Sources/readback-cli/main.swift#L39), [Prompt fallback](../../Sources/readback-cli/main.swift#L250), [Session logging](../../Sources/Readback/Preferences.swift#L76), [Reader diagnostic](../../Sources/Readback/Reader.swift#L66), [Port collision diagnostic](../../Sources/Readback/SpeechMakers.swift#L261), [Log.swift](../../Sources/Readback/Log.swift#L13)

**Fix.** Log event codes and parsing outcomes without raw user text, session IDs, or project paths. Apply explicit private permissions to history and logs and guard against inadvertent disclosure with diagnostic exports. Keep public OSLog fields limited to known-safe metadata.

### S04 · Medium · The local HTTP server has no deadline or aggregate request limit

The parser limits declared bodies, but applies the header ceiling only before finding the terminator. More importantly, the listener retains partial connections and allows unbounded pending work without a deadline or connection cap. Sustained traffic from a reachable client can retain resources and queue work on the main actor. Static verification established the missing controls. No load attack or threshold measurement was performed. Add deadlines, caps, strict framing, and rate limits at the listener. [ControlServer receive loop](../../Sources/Readback/ControlServer.swift#L65), [HTTPRequest.parse](../../Sources/ReadbackCore/HTTPRequest.swift#L19)

### S05 · Medium · History privacy relies on ancestor permissions

A scratch call to the real `ReplyHistory.save` created a `0644` history file with full text and source metadata. This confirms broad file mode, with effective access depending on parent directory permissions and ACLs. On this Mac, the private Library ancestor protected the default path. Explicitly create and migrate owner-only storage, including backups and log files, so a shared alternate path or exported folder has an appropriate default. [ReplyHistory.save](../../Sources/ReadbackCore/ReplyHistory.swift#L115), [ReadbackPaths](../../Sources/ReadbackCore/IntegrationFiles.swift#L20)

### S06 · Supply-chain verification gap

The app pins the top-level MLX Audio version and direct wheel URL, while the installer resolves unpinned transitive dependencies and model revisions at install time. The release builder copies the `uv` selected by the build environment. The published archive matched GitHub's recorded digest. A full installed-dependency advisory sweep and provenance audit were outside this review, and no specific dependency compromise is established. Pin a tested dependency/model set and record the helper versions and digests in the release process. [Installer packages](../../Sources/Readback/Runtime.swift#L17), [Model download](../../Sources/ReadbackCore/ModelCache.swift#L148), [Build script](../../scripts/build-app.sh#L15)

## Deep Review and Sentry Find Bugs

### B01 · Critical · Connecting OpenCode destroys a pre-existing plugin

**Trigger and impact.** An existing `plugins/readback.js` with unrelated contents reports as disconnected. Connect replaces it without a backup. Disconnect removes the replacement and the original is gone. In a scratch home using the actual integration code, the results were `overwritten=true`, `backupExists=false`, and `originalExistsAfterDisconnect=false`. This contradicts the backup and ownership guarantee in the user guide.

**Fix.** Refuse an unowned file or use a distinct plugin path. Preserve a pre-change copy before replacing an owned file, and require a reliable ownership check on disconnect. [ReadbackPaths](../../Sources/ReadbackCore/IntegrationFiles.swift#L62), [IntegrationFiles connect](../../Sources/ReadbackCore/IntegrationFiles.swift#L124), [IntegrationFiles disconnect](../../Sources/ReadbackCore/IntegrationFiles.swift#L140), [User guide](../README-for-friends.md#L38)

### B02 · High · The published release cannot run on Intel

The README explicitly supports macOS voices on Intel, but both Swift executables and bundled `uv` in the published v0.4.0 archive are `arm64` only. I checked the downloaded asset against the GitHub SHA-256 and ran `lipo -archs` on all three binaries. The clean local build produces the same architecture. Publish and test a universal app or explicitly separate supported releases and update the download and setup instructions. [README](../../README.md#L11), [Build script](../../scripts/build-app.sh#L15), [Release](https://github.com/iykazrji/readback/releases/tag/v0.4.0)

### B03 · High · The playback queue can stall or play newer replies before older ones

The oldest waiting entry is marked played before the reader checks that it contains anything speakable or that synthesis succeeds. On empty input the reader returns, and on synthesis failure it moves to `.failed`. Only `.finished` schedules the next entry. Later waiting replies can remain stuck. Also, during the 0.8-second interval after a natural finish, a new automatic reply sees the reader as idle, starts immediately, and cancels the pending FIFO advance. The user's **Wait** preference therefore produces different ordering based on when the last chunk finishes. Centralize queue advancement on terminal outcomes, reserve the next FIFO entry across the hand-off, and mark played only when audio begins. [AppDelegate phase subscription](../../Sources/Readback/AppDelegate.swift#L60), [Queue and playback](../../Sources/Readback/AppDelegate.swift#L224), [Reader start and failure](../../Sources/Readback/Reader.swift#L63)

### B04 · High · History saves can fail while the app reports success

A disk or permissions error leaves the prior history file in place. `Replies.change` publishes the in-memory edit and catches the save failure. A hook still receives HTTP 202, and the History UI can say **Cleared**. If the old file remains readable, restarting restores the supposedly removed entries. Separately, load conflates a missing file with an unreadable or undecodable file. When saving works again, the next reply can replace the only recovery copy with an empty history plus the newest entry. Distinguish absent, corrupt, and valid data, preserve unreadable history for recovery, and surface durable-save failures to callers. [Replies.swift](../../Sources/Readback/Replies.swift#L14), [History mutation](../../Sources/Readback/Replies.swift#L49), [History loading and saving](../../Sources/ReadbackCore/ReplyHistory.swift#L108), [HTTP delivery](../../Sources/Readback/ControlServer.swift#L105), [Clear and undo](../../Sources/Readback/Window/HistoryPages.swift#L216)

### B05 · High · Codex can appear connected after approval is stale

Reconnect after moving the app changes the generated hook commands. Readback treats any nonempty saved trust hash under each event's key as approval, so a previous approval can still make the UI say connected. Codex checks the hash against the current definition and skips hooks with stale trust. The apparent successful reconnect can disable both reading and command interception. Query actual hook readiness or verify the current definitions against the stored trust. Surface an unknown status when exact verification is unavailable. Keep approval with the user. [Hook generation](../../Sources/ReadbackCore/Codex.swift#L23), [Approval parser](../../Sources/ReadbackCore/Codex.swift#L125), [Integration status](../../Sources/ReadbackCore/IntegrationFiles.swift#L220), [Codex hook trust](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)

### B06 · High · Scrubbing a paused reply can resume it at the wrong point

While later audio is still generating, seek within an ungenerated chunk. `Reader.play` stores the chunk index but drops the offset and autoplay intent. On generation completion it starts from the beginning with default autoplay. A scratch probe used production Reader and AVPlayer with gated CAF generation. Seeking to 75% while paused yielded `preparing, chunk=1, progress=0.5`, then `playing, chunk=1, progress=0.5` when the target became available. Retain index, fractional offset, and play/pause intent as a pending seek. Present a consistent transport action while waiting. [Reader generation](../../Sources/Readback/Reader.swift#L91), [Reader seek and play](../../Sources/Readback/Reader.swift#L190), [Player controls](../../Sources/Readback/PlayerView.swift#L292)

### B07 · High · Unlinking a tool can remove hooks that Readback did not author

Hook ownership is inferred from a path substring anywhere in a command, so a legitimate custom hook that calls, logs, or otherwise mentions that helper can be deleted during Connect or Disconnect, including from unrelated event groups. Integration edits also read and write the whole settings document without coordination across the app, CLI, and agents. Concurrent changes can be lost, and a later no-op rewrite can replace the sole backup. Repeating Connect with a temporary Claude settings file replaced the byte-for-byte original backup with a file containing Readback hooks. Match only generated commands or per-entry ownership records. Preserve exact original bytes for rollback and serialize the read/merge/backup/write transaction. [Hook recognition and filtering](../../Sources/ReadbackCore/Integrations.swift#L38), [Claude connect/disconnect](../../Sources/ReadbackCore/Integrations.swift#L123), [Integration file writes](../../Sources/ReadbackCore/IntegrationFiles.swift#L289), [In-process Connections queue](../../Sources/Readback/Connections.swift#L24)

### B21 · High · OpenCode V2 can appear connected without running the plugin

Readback writes a V1 plugin function with a returned event callback and reports connected based on the generated file and CLI path alone. OpenCode documents that V1 plugin implementations do not run on the V2 API. An OpenCode V2 user can follow setup successfully without receiving speech or scoped stop. This follows the published host contract. The locally available host was version 1.18.33. Detect and report supported versions, add a V2 adapter, and test delivery and stop with actual events from each supported host. [Plugin generation](../../Sources/ReadbackCore/Integrations.swift#L173), [OpenCode status](../../Sources/ReadbackCore/IntegrationFiles.swift#L113), [OpenCode migration guide](https://opencode.ai/docs/build/plugins/migrate-v1)

### B08 · Medium · A missing or unrelated stop owner can stop other playback

The HTTP stop route conflates malformed request data with a deliberate global stop. The two automated CLI hooks also turn a missing session ID into a stop with empty scope. Even a valid named session stops ownerless playback, such as a voice sample or `readback say`, because the app treats nil owner as matching. Separate explicit global stop from hook stop, reject malformed or missing hook session IDs, and require an owner match to stop speech. [ControlServer stop](../../Sources/Readback/ControlServer.swift#L114), [CLI hook stop](../../Sources/readback-cli/main.swift#L243), [AppDelegate stopSession](../../Sources/Readback/AppDelegate.swift#L273)

### B09 · Medium · Codex can lose the last reply used by `/read`

With Readback closed and auto-read disabled, the Stop hook deliberately leaves the reply out of app history. Later `/read` starts Readback and searches only its retained history, then claims the chat never replied or replays an older one. The generic transcript fallback used by Stop also expects Claude message records, so it cannot recover a Codex rollout when the optional last-message field is absent. Implement a tool-specific current-session replay source and distinguish unavailable history in the user message. [Transcript fallback](../../Sources/readback-cli/main.swift#L128), [Stop delivery decision](../../Sources/readback-cli/main.swift#L206), [Codex replay](../../Sources/readback-cli/main.swift#L284), [App replay handler](../../Sources/Readback/AppDelegate.swift#L289), [Codex hooks](https://learn.chatgpt.com/docs/hooks)

### B10 · Medium · Concurrent neural operations lose ownership of work

Launch warmup, sample/playback, and **Download now** can overlap. The server actor suspends at downloads and readiness probes, allows tasks for multiple models, and stores only one download process and one visible progress record. A second download overwrites that process and progress state. Completion of either can clear the active handle, and model warmups can load multiple models or restart the engine while another caller uses it. Serialize model transitions or give each operation an ID and explicitly track every owned process. [Warmup call sites](../../Sources/Readback/AppDelegate.swift#L195), [VoiceServer lifecycle](../../Sources/Readback/SpeechMakers.swift#L157), [Download tracking](../../Sources/Readback/SpeechMakers.swift#L302), [ModelDownloads.swift](../../Sources/Readback/ModelDownloads.swift#L27)

### B11 · Medium · Runtime cancel and removal can report the wrong state

During a model download, **Cancel** terminates the tracked installer process and cancels the install task, but the voice server's shared download may continue and the installer already wrote its receipt. A later refresh can report installed after failure or cancellation. For a cancelled update, the cancellation handler calls `refresh()` while state is still `.installing`, so refresh exits and the UI can stay stuck through the rest of the run. A scratch probe against production Runtime, using a temporary home and a harmless stand-in helper, still reported installing after cancellation, helper exit, and explicit refresh. Removal is also scheduled asynchronously, and the HTTP command returns the previous state before the remove operation reports disk failure or completion. The uninstall guide immediately quits after this request. Distinguish package installation from model readiness, propagate cancellation for installer-owned work, and acknowledge completion or error for removal. [Runtime update](../../Sources/Readback/Runtime.swift#L68), [Runtime refresh](../../Sources/Readback/Runtime.swift#L106), [Receipt and cancellation](../../Sources/Readback/Runtime.swift#L156), [Runtime removal](../../Sources/Readback/Runtime.swift#L209), [Engine route handlers](../../Sources/Readback/AppDelegate.swift#L309), [Uninstall guide](../../AGENT-SETUP.md#L116)

### B12 · Medium · A rejected voice request still changes the saved engine

The CLI accepts engine and voice in one command. A valid engine with a mismatched voice ID returns HTTP 400 after the app has already persisted the engine. Validate all fields against the intended voice setup, then write preferences once the request is valid. [CLI voice command](../../Sources/readback-cli/main.swift#L307), [AppDelegate setVoice](../../Sources/Readback/AppDelegate.swift#L332), [Preferences](../../Sources/Readback/Preferences.swift#L10)

### B13 · Medium · Hook deadlines can expire during legitimate app startup

Codex and Claude Stop hooks have 10-second timeouts, but the CLI's 32 polling attempts each have their own timeout and can add more than eight seconds of sleep plus health and speech requests. Flushing stdout early leaves the process running. The connections queue also uses an unbounded Codex subprocess and can block every later connection action if one command hangs. Use an overall time budget with phase-specific errors, and align hook deadlines, delivery acknowledgement, and process command timeouts. [Codex hooks](../../Sources/ReadbackCore/Codex.swift#L61), [Claude hooks](../../Sources/ReadbackCore/Integrations.swift#L123), [CLI readiness](../../Sources/readback-cli/main.swift#L99), [Codex subprocess](../../Sources/ReadbackCore/Codex.swift#L349)

### B14 · Medium · Codex migration can fail after the plugin is installed

The connect flow installs the new plugin before checking and removing legacy hooks. A malformed legacy file causes a failure after plugin changes have taken effect, and the status query checks the same legacy file first and throws. The test named for rejection of broken JSON instantiates the helper without a Codex runner, so it can pass before reaching the bad file. Validate existing configuration first and make enabling the replacement and retiring old hooks recoverable. [Connect and status](../../Sources/ReadbackCore/IntegrationFiles.swift#L192), [Legacy hook cleanup](../../Sources/ReadbackCore/IntegrationFiles.swift#L272), [Integration test](../../Tests/ReadbackCoreTests/IntegrationFilesTests.swift#L98)

### B15 · Medium · History stays over its promised retention limit

The cap is applied on add and restore, with waiting entries protected. After processing or stopping a backlog, mark changes entries to played or kept without reapplying the cap. In the scratch history probe, marking 60 queued replies kept and reloading showed 60 stored entries against a limit of 50. Trim on transitions out of the queue, and keep a separate, explicit policy for a queue with no free slots. [ReplyHistory add and mark](../../Sources/ReadbackCore/ReplyHistory.swift#L51), [Startup conversion](../../Sources/Readback/Replies.swift#L14), [Stop conversion](../../Sources/Readback/AppDelegate.swift#L233)

### B16 · Medium · Readback can treat a partial model cache as ready

The cache check counts weights, bytes, and broken links. For custom models, a single weight file and no dangling link is sufficient even if configuration, tokenizers, or later shards are missing. For built-ins, byte slack can also absorb missing small files. The subsequent load may fetch silently or fail offline after the UI already considered the model downloaded. Use the expected revision's required files or a verified completion receipt instead of inferring completion from size. [ModelCache.snapshot](../../Sources/ReadbackCore/ModelCache.swift#L35), [Completeness heuristic](../../Sources/ReadbackCore/ModelCache.swift#L73), [VoiceServer ensureDownloaded](../../Sources/Readback/SpeechMakers.swift#L302)

### B17 · Medium · Setup and settings can misstate the options the user has

Copyable command examples render a word-joiner inside slash commands. When that character is copied, the produced string differs from the real command. Runtime controls also disappear when the macOS voice is selected, including **Cancel** or **Remove…** for an active or installed neural runtime. An install can switch the selected engine back to Kokoro after the user picks macOS during the download. Use literal command strings and display runtime controls independently of selected voice. Preserve user changes made after the install begins. [ConnectionSettings.swift](../../Sources/Readback/Window/ConnectionSettings.swift#L97), [SetupSheet.swift](../../Sources/Readback/Window/SetupSheet.swift#L176), [VoicesPage.swift](../../Sources/Readback/Window/VoicesPage.swift#L18), [Runtime completion](../../Sources/Readback/Runtime.swift#L119)

### B18 · Medium · Controls and counters show success before audio playback

The app counts a whole reply's words before synthesis starts, including failed and immediately stopped replies. It also marks a blank or unspeakable reply as played and sends a success response even when the prior reply remains audible. History and the sidebar can continue to indicate reading while a finished or failed panel remains open. Record audio start and playback progress from the Reader, and derive status from phase and active item identity. ### B19 · Medium · Escape and auto-hide settings take effect late for a visible player

The panel reevaluates Escape capture and hide timing on reader/list/panel transitions. Updating preferences while it is already visible does not immediately update the global hotkey or a hide task. In the interval, system Escape may still go to Readback after a user disables it, and changing the finished panel's idle timeout can have the opposite effect until the phase changes. ### B22 · Medium · Supported Markdown forms bypass speech cleanup

The cleanup recognizes exactly three backticks as a fence and only treats a line as a table when it has both edge pipes. In benign core probes, a valid tilde fence and a Swift example inside a four-backtick fence left code in the spoken text. A Markdown table without edge pipes also survived. Use a structural Markdown parser or track fence character, fence width, and table boundaries. Cover valid examples from the agent formats Readback consumes. ### B23 · Medium · Integration status can report working before it is usable

Claude connection status accepts a single matching hook and never validates the copied mod, so a partially removed installation can look connected. The Home count includes unapproved Codex registrations, and the main Codex row can count a reply from Orca as proof of delivery because both builds use the same source label. The Connections UI offers only Reconnect or Update for some previously connected states, leaving no direct UI Disconnect. Compute readiness from the required hooks and present connection, approval, last delivery, and removal actions independently.
